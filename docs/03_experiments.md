# 03. 비교 실험 설계

목적: "시뮬레이션/저작은 Omniverse 계열, 운영자 클라이언트는 UE"라는 역할 분리의 **근거를 측정**한다. 결과가 반대로 나와도 그대로 기록한다.

## 공통 조건
- 같은 USD 씬(`usd/scenes/hall01.usd`), 같은 카메라 경로, 같은 센서 시나리오 `cooling_failure`.
- 측정 PC: RTX 5090 32GB, 9950X3D, RAM 126GB. 드라이버/엔진/라이브러리 버전을 결과표에 기록.
- 각 항목 5회 반복, 중앙값과 범위를 기록.

## E1. UE ↔ USD 변환 손실
| 항목 | 방법 | 기록 |
|---|---|---|
| 계층/네이밍 | prim 경로 vs UE 액터 계층 비교 | 일치율 |
| 메타데이터(`dct:`) | USD 속성이 UE에서 접근 가능한가 | 가능/불가, 우회법 |
| 머티리얼 | 같은 프리뷰 머티리얼 렌더 비교 | 스크린샷, 차이 목록 |
| 인스턴싱/폴리곤 | 랙 20기 기준 | 드로우콜, 메모리 |
| USD 사용자 속성 읽기 (결정 D3) | Unreal에서 `dct:` 속성을 읽을 수 있는지 | 가능/불가, 방법. 불가여도 센서 매니페스트로 진행 가능([ADR-005](decisions/ADR-005-sensor-anchors-and-manifest.md)) |
| 재질 대체 | 가져온 서버 앞면 메시에 온도 색 재질(Custom Primitive Data)을 연결하는 방법 | 가져올 때 대체 vs 실행 중 대체, 성공 여부 |
| 센서 앵커 위치 | 앵커 위치가 Unreal에서 같은 위치로 보이는지 | 오차 (cm) |
| 매니페스트 일치 | 매니페스트의 센서 80개와 Unreal에서 찾은 앵커 수 | 일치율 |

## E2. Omniverse 단독(ovrtx 뷰어) vs UE 클라이언트
| 항목 | 측정 |
|---|---|
| UI 개발 비용 | 동일 패널(센서 리스트+알람) 구현 소요 시간, 코드 줄 수 |
| 런타임 성능 | 평균/1% low FPS, 로딩 시간, VRAM |
| 시각 품질 | 동일 카메라 스크린샷 비교 |
| **Unreal 고유 기능 구현 비용** | 같은 기능(1인칭 걸어 다니기, 랙 문 열기, 기류 입자 효과)을 Unreal과 Omniverse 쪽에서 각각 만드는 데 걸린 시간, 코드 양, 막힌 점 ([12](12_unreal_design.md) 11장) |
- B안은 `D:\omniverse-labs-main`의 `ovrtx` 뷰어 패턴을 **참조**하되 코드는 `experiments/`에 새로 작성한다(Apache-2.0 고지 확인).

## E3. 서비스 방식 비교
| 방식 | 측정 |
|---|---|
| exe 패키징 | 입력→화면 지연, 시작 시간 |
| Pixel Streaming (LAN) | 지연, 비트레이트, 텍스트 가독성 |
| Pixel Streaming (원격/임시 클라우드) | 지연, 끊김 |
| 동시 접속 | 5090 1대에서 인스턴스 N개일 때 GPU/VRAM, 품질 저하 시점 |

## E4. UI 방식 A/B
