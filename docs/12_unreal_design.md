# 12. Unreal 클라이언트 설계

- 상태: 초안 v1 (2026-10-15). 코드를 쓰면서 클래스 이름과 구성이 바뀔 수 있고, 바뀌면 이 문서를 먼저 고친다.
- 목적: Unreal 프로젝트 `DataCenter_DT`의 구성, 데이터 흐름, 화면, 시험 방법을 정한다.
- 관련 문서: [11 데이터 규격](11_data_spec.md), [09 USD 규격](09_usd_spec.md), [ADR-003](decisions/ADR-003-delivery-and-ui.md), [ADR-004](decisions/ADR-004-streaming-hosting.md)
- 전제: 이 프로젝트의 코드는 모두 새로 작성한다. 다른 프로젝트의 클래스를 복사하지 않는다.

## 1. 목표와 하지 않을 것

| 목표 | 하지 않을 것 |
|---|---|
| 운영자가 홀 전체 상태를 3D와 목록으로 본다 | 장비 제어(명령 전송). 읽기 전용 |
| 알람이 생기면 해당 장비를 바로 찾아 간다 | 사용자 로그인과 권한 |
| 센서 값 변화를 그래프로 확인한다 | 과거 데이터 영구 저장 |
| 열·기류 볼륨을 3D로 본다(Phase 4) | 정확한 열 해석 |
| 내부를 걸어 다니며 둘러보고 안내 투어를 본다(10장) | 장비 안쪽(서버 내부) 세부 모델링 |
| Unreal 고유 기능으로 현장감을 높인다(11장) | 모든 기능을 Omniverse와 일대일로 맞추기 |
| 브라우저(Pixel Streaming)와 exe 양쪽에서 동작 | 모바일 앱, XR |

## 2. 프로젝트 구성

C++ 모듈 하나(`DataCenter_DT`)에 폴더 5개를 둔다. 클래스 접두는 `DCT`.

```
unreal/DataCenter_DT/Source/DataCenter_DT/
  Core/        설정, 로그, 공용 타입
  Data/        게이트웨이 연결, 센서 목록(레지스트리), 알람 모델, 이력 버퍼
  World/       3D 장면 연동: 센서 앵커 찾기, 온도 색 표시, 선택·강조, 카메라
  UI/          CommonUI 기반 화면(Foundation → Components → Panels)
  Streaming/   Pixel Streaming 연동, 웹 패널과의 메시지 교환
```

의존 방향: `UI` → `Data`, `World` → `Data`, 모두 → `Core`. **`Data`는 `UI`와 `World`를 모른다.** 그래서 화면 없이도 데이터 계층을 시험할 수 있다.

| Data | `UDCTAlarmModel` | 게이트웨이가 보낸 알람 상태 보관, 목록과 변화 이벤트 제공 |
| World | `UDCTSceneBinder` | 매니페스트의 `usdPath`로 장면의 오브젝트를 찾아 센서와 연결 |

## 4. 데이터 흐름

```
게이트웨이 ──WebSocket──▶ UDCTConnectionSubsystem
                              │ (snapshot / sample / alarm)
                              ▼
                    UDCTSampleStore, UDCTAlarmModel   ◀── UDCTSensorRegistry (매니페스트)
                              │ (변화 알림: 델리게이트)
              ┌───────────────┼────────────────┐
              ▼               ▼                ▼
        UI 패널들      UDCTHeatTintComponent   ADCTCameraPawn(알람 포커스)
```

- **시작 순서:** ① 매니페스트를 받는다(`GET /api/sensors`) → ② 센서 레지스트리 구성 → ③ 장면 연결(`SceneBinder`) → ④ WebSocket 접속 → ⑤ `snapshot` 반영.
- **매니페스트를 못 받으면** 화면에 오류를 보이고 재시도한다. 센서 값이 먼저 와도 레지스트리에 없으면 무시하고 로그를 남긴다.
- **연결이 끊기면** 마지막 값을 유지하고 화면 위에 "연결 끊김" 표시를 띄운다. 값은 `stale`로 표시한다.
- 값의 갱신은 **게임 스레드에서만** 한다. 네트워크 수신은 받은 즉시 큐에 넣고 틱에서 처리한다.

## 5. 온도를 3D 장비에 색으로 입히기

**방법:** 서버 앞면 메시(`M_ServerFront` 재질을 쓰는 부분)에 **인스턴스별 값**(Custom Primitive Data)을 넣는다. 재질은 이 값(정규화한 온도, 0~1)을 읽어 색을 정한다.

| 항목 | 설명 |
|---|---|
| 재질 | `M_ServerFront`를 부모로 한 재질에서 Custom Primitive Data 0번을 읽고 색 곡선으로 변환 |
| 갱신 | `SetCustomPrimitiveDataFloat(0, 값)` |
| 장점 | 랙 60기가 **같은 재질**을 쓰면서도 각자 다른 색을 가질 수 있다. 재질 인스턴스를 60개 만들 필요가 없다. |
| 값 정규화 | `(값 − 최소) / (최대 − 최소)`. 범위는 매니페스트의 `range` |
| 알람 강조 | 알람 상태가 `warn`/`critical`이면 외곽선 또는 발광을 추가(Phase 5) |

USD로 가져온 메시에 이 재질을 연결하는 방법(가져올 때 재질 대체 vs 실행 중 대체)은 Phase 2의 E1에서 확인한다.

## 6. 화면 구성

```
┌───────────────────────────────────────────────────────────┐
│ 상단 바: 연결 상태, 시나리오 이름, 시간                       │
├───────────────┬───────────────────────────┬───────────────┤
│ 왼쪽          │                           │ 오른쪽         │
│ 알람 목록      │       3D 뷰               │ 선택한 장비의   │
│ (위험→주의→    │   (랙, 히트 색, 강조)       │ 센서 값과 그래프 │
│  시간순)       │                           │               │
├───────────────┴───────────────────────────┴───────────────┤
│ 하단: 시나리오 제어(개발용), 범례(온도 색)                    │
└───────────────────────────────────────────────────────────┘
```

| 패널 | 내용 | 만드는 때 |
|---|---|---|
| 알람 목록 | 현재 알람, 클릭하면 해당 장비로 카메라 이동 | Phase 5 |
| 센서 상세 | 선택한 장비의 센서 목록과 현재 값 | Phase 3 |
| 추이 그래프 | 선택한 센서의 최근 값 | Phase 5 (UMG 또는 웹 패널, E4에서 비교) |
| 개요 | 홀 전체 평균·최고 온도, 알람 개수 | Phase 5 |
| 시나리오 제어 | 시나리오 시작/종료 (개발·시연용) | Phase 3 |
| 상태 표시줄 | 연결 상태, 마지막 갱신 시각 | Phase 3 |

UI는 CommonUI로 만들고, 기초 부품(버튼, 레이블, 카드) → 조합 부품 → 패널의 순서로 계층을 나눈다. 디자인은 어두운 배경에 상태 색(정상 초록, 주의 노랑, 위험 빨강)을 쓰되, **색만으로 상태를 구분하지 않고** 아이콘과 글자를 함께 쓴다.

## 7. Pixel Streaming과 웹 패널

| 항목 | 내용 |
|---|---|
| 플러그인 | PixelStreaming2 (UE 5.8에 포함, 동작은 Phase 6에서 확인) |
| 입력 | 마우스, 키보드. 모바일 터치는 지원하지 않는다. |
| 해상도 | 브라우저 창 크기에 맞춤. 기본 1920 x 1080, 최대 비트레이트는 측정 후 정함 |
| 웹 패널 | 추이 그래프 등 텍스트가 많은 패널을 브라우저 쪽에서 그리는 방식(E4에서 비교). Unreal과는 데이터 채널로 JSON 메시지를 주고받는다. |
| 교환 메시지 | Unreal → 웹: 선택한 센서 ID, 최근 샘플. 웹 → Unreal: 센서 선택, 카메라 이동 요청 |

## 10. 내부 둘러보기 (걸어 다니며 보기)

데이터센터 안을 직접 걸어 다니며 장비와 센서 값을 보는 기능이다. 운영 화면의 "전체 보기"와 달리 **눈높이에서 현장을 체험**하는 용도다.

### 10.1 모드
| 모드 | 설명 | 조작 |
|---|---|---|
| 전체 보기 | 홀 전체를 위에서 돌려 보는 기존 화면 | 마우스 드래그로 회전, 휠로 확대 |
| **걸어 다니기** | 1인칭으로 통로를 걷는다. 벽과 장비에 부딪힌다. | WASD 이동, 마우스 시점, Shift 빠르게 |
| **안내 투어** | 정해 둔 지점을 카메라가 자동으로 돌며 설명을 보여 준다. | 다음/이전/멈춤 |
| 알람 현장으로 | 알람을 누르면 해당 장비 앞으로 이동한다. | 클릭 |

### 10.2 걸어 다닐 때의 정보 표시
- 시선이 닿은 장비를 강조하고 센서 값을 작은 패널(툴팁)로 보여 준다.
- 가까운 랙 위에만 값 라벨을 띄운다(거리 제한, 화면이 복잡해지지 않게).
- 화면 구석에 **평면도(미니맵)** 를 두고 현재 위치와 알람 위치를 표시한다.
- 걸어 다니는 중에도 알람이 생기면 화면 위에 알림을 띄우고, 눌러서 이동할 수 있다.

### 10.3 이동 규칙 (초안, 측정 후 조정)
| 항목 | 값 |
|---|---|
| 눈높이 | 165 cm |
| 걷기 속도 | 약 150 cm/s, Shift를 누르면 약 300 cm/s |
| 충돌 | 캡슐 모양 충돌, 벽과 장비를 따라 미끄러진다 |
| 통로 폭 | 차가운 통로 120 cm 이상, 뜨거운 통로 100 cm 이상 (모델링 기준) |

### 10.4 안내 투어
- 투어 지점은 USD의 **투어 앵커**로 정의한다([09](09_usd_spec.md) 11장). 지점마다 제목, 설명, 강조할 장비가 있다.
- 지점 사이 이동은 시퀀서(Sequencer)로 만든 카메라 경로 또는 스플라인 이동을 쓴다.
- 투어 중에도 센서 값은 실시간으로 갱신된다.

### 10.5 Pixel Streaming에서의 주의
- 브라우저에서 마우스 시점 조작은 **마우스 잠금(Pointer Lock)** 이 필요하다. 지원 여부와 사용성을 Phase 6에서 확인한다. 안 되면 드래그 방식 시점을 쓴다.
- 키보드 입력의 지연이 걷는 느낌에 영향을 준다. 지연은 E3에서 측정한다.
- 눈높이에서는 한 화면에 보이는 장비 수가 많아 그리는 부담이 커진다. 컬링과 단계별 상세도(LOD), 값 라벨 거리 제한으로 대응하고 **프레임 속도를 측정**한다.

### 10.6 모델링에 주는 영향
데이터센터 내부가 곧 장면이라 **방을 따로 모델링하지 않는다.** 바닥, 벽, 천장은 장면 생성 스크립트가 상자로 만들고 충돌로도 쓴다. 통로 폭 기준만 지키면 된다([09](09_usd_spec.md) 11장).

## 11. Unreal 고유 기능 (Unreal에서 기본 제공되어 만들기 쉬운 것)

이 프로젝트에서 Unreal을 운영 화면에 쓰는 근거를 강화하는 기능이다. "Omniverse로는 만들 수 없다"는 뜻이 아니다. Kit 앱에서도 직접 구현할 수 있는 것이 있을 수 있어서, **같은 기능을 양쪽에서 만드는 비용을 비교 실험(E2)에서 측정**한다.

| 기능 | Unreal에서 쓰는 것 | 이 프로젝트에서의 모습 | Omniverse 쪽 (미확인) | Phase |
|---|---|---|---|---|
| 1인칭 이동과 충돌 | 게임 프레임워크(캐릭터, 충돌, 향상된 입력) | 걸어 다니기 (10장) | Kit에서 직접 구현해야 할 가능성. 확인 필요 | 5 |
| 상호작용 | 블루프린트, 상호작용 시스템 | 랙 문 열기, 서버 선택해 상세 보기 | 확인 필요 | 5 |
| 실시간 시각 효과 | 나이아가라(Niagara) | 공기 흐름 입자, 알람 발광, 열기 일렁임을 센서 값에 연동 | Flow, 확인 필요 | 5 |
| 영상 연출과 녹화 | 시퀀서(Sequencer), Movie Render Queue | 안내 투어 카메라, **포트폴리오 데모 영상 제작** | 확인 필요 | 5, 8 |
| 공간 음향 | MetaSounds, 3D 사운드 | 팬 소리가 팬 속도에 따라 변함, 알람음. 걸을 때 몰입감 | 확인 필요 | 5 |
| 실시간 조명 | Lumen, 나이아가라와 연계 | 알람 시 조명 변화(비상등) | 확인 필요 | 5 |
| 3D 알람 강조 | 렌더 파이프라인의 커스텀 스텐실과 후처리 머티리얼 | 알람 장비만 외곽선과 발광으로 강조(깜빡임, 거리별 단계) | 확인 필요 | 5 |
| 외부에서 장면 제어 | Remote Control API(REST, WebSocket) | 웹 패널이나 외부 도구가 선택, 카메라 이동, 시나리오 전환을 호출 | 확인 필요 | 6 |
| 흐름 표현 머티리얼 | 머티리얼 그래프(흐름 방향과 속도 애니메이션) | 냉기와 열기의 흐름 방향을 장비와 바닥에 표현 | 확인 필요 | 4~5 |
| AI 채팅 패널 (선택) | UMG와 HTTP/WebSocket 연동 | 알람을 묻고 요약을 받는 패널 | 해당 없을 가능성 | 선택(Phase 9) |
| 대응 훈련 모드 (선택) | 게임 상태와 블루프린트 | 알람 상황에서 점검 절차를 순서대로 수행하는 연습 | 해당 없을 가능성 | 선택 |
| 음성 안내 어시스턴트 (선택) | MetaHuman, 음성 합성 립싱크, LLM 연동 | 알람을 말로 안내하는 가상 운영 보조 | 해당 없을 가능성 | 선택(Phase 9) |
| 다중 화면 관제실 (선택) | nDisplay | 여러 모니터에 나누어 보여 주는 관제실 | 해당 없을 가능성 | 선택 |

- "Omniverse 쪽" 열은 **조사한 사실이 아니라 확인할 질문**이다. 근거 없이 단정하지 않는다.
- 선택 항목은 일정 여유와 효과를 보고 정한다. 기본 범위는 위 표의 Phase 5 항목이다.
- 음성 안내 어시스턴트와 MetaHuman은 기존 경력과 이어지는 확장이지만 데이터센터 주제에서 멀어질 수 있어 **선택**으로 둔다.

## 12. 화면 흐름: 외관 → 층 → 둘러보기 (ADR-008, 보조 기능)

> 이 프로젝트의 핵심은 시뮬레이션과 센서 데이터의 연동·표현이다([14](14_sim_to_unreal_core.md)). 외관과 환경은 **보조**이며 최소 버전부터 만든다.

프로그램의 첫 화면은 **데이터센터 외관**이고, 건물을 누르면 **서버 랙 공간(한 층)** 으로 들어가며, 거기서 전력과 열 정보를 보고 **그 공간을 걸어 다닐 수 있다.** 자세한 결정은 [ADR-008](decisions/ADR-008-screen-flow-exterior-to-floor.md)에 있다.

### 12.1 세 단계 화면

| 단계 | 화면 | 보이는 것 | 할 수 있는 것 |
|---|---|---|---|
| 1. 외관 | 데이터센터 건물과 주변 환경(하늘, 땅, 식생, 옥외 설비) | 현실적인 건물, 옥외 냉각 설비와 발전기, 건물 전체 전력과 효율 요약 | 건물에 마우스를 올리면 강조, **클릭하면 층으로 들어간다.** 궤도 카메라 |
| 2. 층(서버 랙 공간) | 건물 외벽이 열리듯 사라지며 해당 층의 랙 공간이 나타남 | 랙, 냉각 장치, 센서 값에 따른 온도 색 | 전력량 패널, 열 이동 시뮬레이션(히트맵과 기류 볼륨 전환), 알람, 시나리오 선택 |
| 3. 둘러보기 | 같은 공간을 1인칭으로 | 눈높이에서 본 랙과 통로, 가까운 장비의 값 | 걸어 다니기, 안내 투어(10장) |

`뒤로 가기`로 단계를 거꾸로 이동한다(둘러보기 → 층 → 외관).

### 12.2 전환 방식
- **외관 → 층:** 카메라가 건물로 다가가고, 해당 층의 외벽과 위층이 투명해지면서(단면, 컷어웨이) 안쪽 랙 공간이 보인다. 상세한 층은 **별도 레벨(서브레벨)** 로 두고 필요할 때 불러온다(레벨 스트리밍). 외관에서는 층 내부를 불러오지 않아 가볍다.
- **층 → 둘러보기:** 궤도 카메라에서 1인칭 캐릭터로 바꾼다. 화면은 같은 공간이라 끊김이 없다.
- 전환 중에도 센서 값은 계속 갱신된다.

### 12.3 외관 화면의 구성
| 요소 | 내용 |
|---|---|
| 건물 | 직접 모델링한 가상 데이터센터 건물(모듈형 외벽, 환기구, 출입구). 외부 모델을 가져오지 않는다. |
| 옥외 설비 | 냉각탑, 발전기, 변전 설비 같은 소품. 일부는 숫자 라벨을 가진다(예: 냉각 전력). |
| 환경 | 하늘과 태양, 구름, 지형, 도로, 울타리, 식생 |
| 정보 | 건물 전체 전력, 효율(PUE), 알람 개수 요약 |
| 시간대 | 낮과 저녁 전환(선택). 분위기 연출에 효과적이다. |

### 12.4 현실적인 환경을 만드는 방법 (Unreal 기능)
| 목적 | 쓰는 기능 |
|---|---|
| 하늘, 태양, 구름 | 하늘 대기(Sky Atmosphere), 부피 구름(Volumetric Clouds), 태양 조명 |
| 빛과 그림자 | Lumen(실시간 전역 조명), 가상 그림자 맵 |
| 큰 지형과 식생 | 랜드스케이프, 절차적 배치(PCG) 또는 식생 도구 |
| 디테일 많은 소품 | Nanite |
| 분위기 | 후처리(색감, 안개), 바람과 새 같은 주변음(MetaSounds) |

- 위 기능은 Unreal이 기본 제공하며, 같은 수준의 외관 장면을 Omniverse 쪽에서 만드는 비용은 E2에서 비교한다.
- **외부 환경 에셋(텍스처, 식생, 하늘 이미지 등)은 저장소에 올리지 않는다.** 용량 문제와 라이선스(재배포 금지) 때문이다. 대신 `docs/ASSET_LICENSES.md`에 **출처, 라이선스, 받는 방법**을 적는다. 저장소를 받은 사람이 같은 에셋을 받아 연결할 수 있게 한다.

## 13. 구현 현황: 데이터 계층 (2026-10-16)
`unreal/DataCenter_DT/Source/DataCenter_DT/`에 `Core`와 `Data` 계층을 만들었다(UE 5.8.3, Windows). 화면(`UI`, `World`)은 아직 없다.

| 파일 | 내용 |
|---|---|
| `Core/DCTTypes` | 센서 값, 알람 상태, 품질, 센서 정보 등 공용 타입 |
| `Data/DCTMessageParser` | 매니페스트(`GET /api/sensors`)와 WebSocket 메시지 읽기. 센서 하나라도 형식이 틀리면 목록 전체를 받지 않는다. 숫자 자리에 문자열(`"24"`)이 오면 거부한다 |
| `Data/DCTSensorModel` | `FDCTSensorRegistry`(센서 목록), `FDCTSampleStore`(최근 값과 이력 원형 버퍼, 과거 시각은 무시), `FDCTAlarmModel`(알람 상태, 기록, 변화 알림) |
| `Data/DCTSensorHub` | 위 셋과 집계, 시나리오를 묶고 메시지를 반영. 목록에 없는 센서는 버리고 로그를 남긴다. 네트워크를 몰라서 자동화 테스트로 검증한다 |
| `Data/DCTConnectionSubsystem` | 게임 인스턴스 서브시스템. 센서 목록을 받고 WebSocket에 접속한다. 받은 메시지는 큐에 넣고 게임 스레드의 틱에서만 처리한다(한 틱 최대 2,000건). 끊기면 값은 두고 `stale`로 바꾸고, 2초에서 10초까지 늘려 가며 다시 연결한다(센서 목록부터 다시 받는다) |

- 설계 문서 3장과 다른 점: `UDCTSensorRegistry`, `UDCTSampleStore`, `UDCTAlarmModel`을 UObject가 아닌 일반 클래스로 만들었다. 엔진 객체 없이 테스트에서 바로 만들 수 있기 때문이다.
- 콘솔 명령(Play 중): `dct.connect [http://127.0.0.1:8080]`, `dct.disconnect`, `dct.status`. 변수 `dct.StatusLogSeconds N`을 주면 N초마다 상태를 로그에 쓴다.
- 자동화 테스트 4개(`DCT.Data.Manifest`, `Message`, `SampleStore`, `Hub`): 모두 통과.
  ```
  UnrealEditor-Cmd.exe DataCenter_DT.uproject -ExecCmds="Automation RunTests DCT.Data; Quit" -unattended -nullrhi -nosplash
  ```
  처음 실행에서 `"24"` 같은 숫자 문자열을 값으로 받아들이는 문제가 나와 숫자만 인정하도록 고쳤다.
- 실제 연결 확인: 게이트웨이를 `cooling_failure` 녹화 재생(`--time-scale 5 --loop`)으로 띄우고 게임 모드(`-game -nullrhi`)로 접속했다. 센서 204개를 받고 약 25초 동안 메시지 15,000건 이상(초당 약 1,000건)을 읽기 실패 0건으로 처리했고, 알람이 22개에서 34개로 시간에 따라 바뀌었다.
- 한계: 화면 없는 확인이다. 틱 시간(프레임 비용)은 측정하지 않았다. `-benchmark`처럼 게임 시간이 빠르게 가는 실행에서는 메시지를 거의 못 받으므로 실제 시간으로 확인해야 한다.

### 13.1 신뢰 구간과 신뢰 등급 표시 (2026-10-26)
센서 생성기 L2(`docs/11` 6.2장)가 랙 입구 온도에 붙이는 90% 구간(`lower`, `upper`)과 신뢰 등급(`confidence`)을 Unreal에서 받아 보여 준다.
- **데이터**: `FDCTSensorSample`에 `Lower`, `Upper`, `Confidence`(`EDCTConfidence`: None, Ok, Caution, Low, Fallback)를 추가했다. 모두 선택 필드다. 구간은 JSON 숫자 둘이고 `lower <= upper`일 때만 받고(숫자 문자열, 순서가 거꾸로면 무시), 모르는 등급은 None이다. 값, 알람, 품질 판정은 바뀌지 않는다.
- **표현**: `ADCTHeatOverlayActor`가 온도 판 위에 얇은 **신뢰 막대**를 세운다. 색은 등급(ok 초록, caution 노랑, low 빨강, fallback 회색), 길이는 구간 폭이다(폭 0이면 판 폭 전체, `ConfidenceFullWidth`(기본 4도) 이상이면 15%). 색만으로 구분하지 않게 길이를 함께 쓴다. 구간과 등급이 없는 센서(L0, L1 데이터)는 막대가 보이지 않는다. `bShowConfidenceBar`로 끌 수 있다.
- **계산**: 색과 길이 계산은 `Core/DCTConfidence.h`에 순수 함수로 두었다.
- **테스트**: `DCT.Data.Confidence` 추가(파싱, 형식이 틀린 입력, 막대 길이, 색). `DCT.Data` 6개 모두 통과.
- **한계**: 막대의 실제 모양은 에디터에서 눈으로 확인하지 않았다(화면 없는 빌드와 테스트까지만). 막대 길이 기준(4도)은 정해 둔 값이며 측정으로 정하지 않았다.
