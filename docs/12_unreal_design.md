# 12. Unreal 클라이언트 설계

- 상태: 초안 v1 (2026-10-15). 코드를 쓰면서 클래스 이름과 구성이 바뀔 수 있고, 바뀌면 이 문서를 먼저 고친다.
- 목적: Unreal 프로젝트 `DCTwin`의 구성, 데이터 흐름, 화면, 시험 방법을 정한다.
- 관련 문서: [11 데이터 규격](11_data_spec.md), [09 USD 규격](09_usd_spec.md), [ADR-003](decisions/ADR-003-delivery-and-ui.md), [ADR-004](decisions/ADR-004-streaming-hosting.md)
- 전제: 이 프로젝트의 코드는 모두 새로 작성한다. 다른 프로젝트의 클래스를 복사하지 않는다.

## 1. 목표와 하지 않을 것

| 목표 | 하지 않을 것 |
|---|---|
| 운영자가 홀 전체 상태를 3D와 목록으로 본다 | 장비 제어(명령 전송). 읽기 전용 |
| 알람이 생기면 해당 장비를 바로 찾아 간다 | 사용자 로그인과 권한 |
| 센서 값 변화를 그래프로 확인한다 | 과거 데이터 영구 저장 |
| 열·기류 볼륨을 3D로 본다(Phase 4) | 정확한 열 해석 |
| 브라우저(Pixel Streaming)와 exe 양쪽에서 동작 | 모바일 앱, XR |

## 2. 프로젝트 구성

C++ 모듈 하나(`DCTwin`)에 폴더 5개를 둔다. 접두는 `DCT`.

```
unreal/Source/DCTwin/
  Core/        설정, 로그, 공용 타입
  Data/        게이트웨이 연결, 센서 목록(레지스트리), 알람 모델, 이력 버퍼
  World/       3D 장면 연동: 센서 앵커 찾기, 온도 색 표시, 선택·강조, 카메라
  UI/          CommonUI 기반 화면(Foundation → Components → Panels)
  Streaming/   Pixel Streaming 연동, 웹 패널과의 메시지 교환
```

의존 방향: `UI` → `Data`, `World` → `Data`, 모두 → `Core`. **`Data`는 `UI`와 `World`를 모른다.** 그래서 화면 없이도 데이터 계층을 시험할 수 있다.

## 3. 주요 클래스 (초안)

| 계층 | 클래스 | 역할 |
|---|---|---|
| Core | `FDCTSensorSample` | 센서 값 한 건(ID, 값, 단위, 품질, 시각) |
| Core | `EDCTAlarmState` | normal, warn, critical |
| Data | `UDCTConnectionSubsystem` | 게이트웨이 WebSocket 연결, 끊기면 다시 연결 |
| Data | `UDCTSensorRegistry` | 매니페스트를 읽어 센서 목록 보관. ID로 센서와 장비 찾기 |
| Data | `UDCTSampleStore` | 센서별 최근 값과 이력(원형 버퍼) |
| Data | `UDCTAlarmModel` | 게이트웨이가 보낸 알람 상태 보관, 목록과 변화 이벤트 제공 |
| World | `UDCTSceneBinder` | 매니페스트의 `usdPath`로 장면의 오브젝트를 찾아 센서와 연결 |
| World | `UDCTHeatTintComponent` | 장비 앞면의 색을 값에 따라 바꾼다(5장) |
| World | `ADCTCameraPawn` | 궤도 카메라, 장비로 이동(포커스) |
| World | `ADCTAirflowVolume` | 열·기류 볼륨 표시 (Phase 4) |
| UI | `UDCTRootLayout` | 화면 전체 틀 |
| UI | `UDCTAlarmListPanel` 등 | 6장 참고 |
| Streaming | `UDCTStreamingBridge` | 브라우저와 데이터 채널로 메시지 교환 |

## 4. 데이터 흐름

```
게이트웨이 ──WebSocket──▶ UDCTConnectionSubsystem
                              │ (snapshot / sample / alarm)
                              ▼
                    UDCTSampleStore, UDCTAlarmModel   ◀── UDCTSensorRegistry (매니페스트)
                              │ (변화 알림: 델리게이트)
              ┌───────────────┼────────────────┐
              ▼               ▼                ▼
        UI 패널들      UDCTHeatTintComponent   ADCTCameraPawn(알람 포커스)
```

- **시작 순서:** ① 매니페스트를 받는다(`GET /api/sensors`) → ② 센서 레지스트리 구성 → ③ 장면 연결(`SceneBinder`) → ④ WebSocket 접속 → ⑤ `snapshot` 반영.
- **매니페스트를 못 받으면** 화면에 오류를 보이고 재시도한다. 센서 값이 먼저 와도 레지스트리에 없으면 무시하고 로그를 남긴다.
- **연결이 끊기면** 마지막 값을 유지하고 화면 위에 "연결 끊김" 표시를 띄운다. 값은 `stale`로 표시한다.
- 값의 갱신은 **게임 스레드에서만** 한다. 네트워크 수신은 받은 즉시 큐에 넣고 틱에서 처리한다.

## 5. 온도를 3D 장비에 색으로 입히기

**방법:** 서버 앞면 메시(`M_ServerFront` 재질을 쓰는 부분)에 **인스턴스별 값**(Custom Primitive Data)을 넣는다. 재질은 이 값(정규화한 온도, 0~1)을 읽어 색을 정한다.

| 항목 | 설명 |
|---|---|
| 재질 | `M_ServerFront`를 부모로 한 재질에서 Custom Primitive Data 0번을 읽고 색 곡선으로 변환 |
| 갱신 | `SetCustomPrimitiveDataFloat(0, 값)` |
| 장점 | 랙 20기가 **같은 재질**을 쓰면서도 각자 다른 색을 가질 수 있다. 재질 인스턴스를 20개 이상 만들 필요가 없다. |
| 값 정규화 | `(값 − 최소) / (최대 − 최소)`. 범위는 매니페스트의 `range` |
| 알람 강조 | 알람 상태가 `warn`/`critical`이면 외곽선 또는 발광을 추가(Phase 5) |

USD로 가져온 메시에 이 재질을 연결하는 방법(가져올 때 재질 대체 vs 실행 중 대체)은 Phase 2의 E1에서 확인한다.

## 6. 화면 구성

```
┌───────────────────────────────────────────────────────────┐
│ 상단 바: 연결 상태, 시나리오 이름, 시간                       │
├───────────────┬───────────────────────────┬───────────────┤
│ 왼쪽          │                           │ 오른쪽         │
│ 알람 목록      │       3D 뷰               │ 선택한 장비의   │
│ (위험→주의→    │   (랙, 히트 색, 강조)       │ 센서 값과 그래프 │
│  시간순)       │                           │               │
├───────────────┴───────────────────────────┴───────────────┤
│ 하단: 시나리오 제어(개발용), 범례(온도 색)                    │
└───────────────────────────────────────────────────────────┘
```

| 패널 | 내용 | 만드는 때 |
|---|---|---|
| 알람 목록 | 현재 알람, 클릭하면 해당 장비로 카메라 이동 | Phase 5 |
| 센서 상세 | 선택한 장비의 센서 목록과 현재 값 | Phase 3 |
| 추이 그래프 | 선택한 센서의 최근 값 | Phase 5 (UMG 또는 웹 패널, E4에서 비교) |
| 개요 | 홀 전체 평균·최고 온도, 알람 개수 | Phase 5 |
| 시나리오 제어 | 시나리오 시작/종료 (개발·시연용) | Phase 3 |
| 상태 표시줄 | 연결 상태, 마지막 갱신 시각 | Phase 3 |

UI는 CommonUI로 만들고, 기초 부품(버튼, 레이블, 카드) → 조합 부품 → 패널의 순서로 계층을 나눈다. 디자인은 어두운 배경에 상태 색(정상 초록, 주의 노랑, 위험 빨강)을 쓰되, **색만으로 상태를 구분하지 않고** 아이콘과 글자를 함께 쓴다.

## 7. Pixel Streaming과 웹 패널

| 항목 | 내용 |
|---|---|
| 플러그인 | PixelStreaming2 (UE 5.7에 포함, 동작은 Phase 6에서 확인) |
| 입력 | 마우스, 키보드. 모바일 터치는 지원하지 않는다. |
| 해상도 | 브라우저 창 크기에 맞춤. 기본 1920 x 1080, 최대 비트레이트는 측정 후 정함 |
| 웹 패널 | 추이 그래프 등 텍스트가 많은 패널을 브라우저 쪽에서 그리는 방식(E4에서 비교). Unreal과는 데이터 채널로 JSON 메시지를 주고받는다. |
| 교환 메시지 | Unreal → 웹: 선택한 센서 ID, 최근 샘플. 웹 → Unreal: 센서 선택, 카메라 이동 요청 |

## 8. 테스트

| 종류 | 대상 | 방법 |
|---|---|---|
| 자동화 테스트 | 매니페스트 파싱, 샘플 저장소(원형 버퍼), 알람 모델 | Unreal 자동화 테스트(Automation) |
| 재생 시험 | 연결부터 화면까지 | 게이트웨이를 녹화 파일 재생 모드로 켜고 알람이 같은 순서로 뜨는지 확인 |
| 성능 | 프레임 속도, 메모리, VRAM | 랙 20기 장면에서 측정(Phase 2, 5). 목표는 측정 후 정한다. |
| 수동 | 연결 끊김, 매니페스트 오류, 센서 누락 | 체크리스트(Phase 5) |
