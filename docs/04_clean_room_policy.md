# 04. 클린룸 / 공개 정책

공개 포트폴리오와 재직 회사 업무 자산을 분리하기 위한 규칙.

## 원칙
1. 이 저장소의 모든 코드·모델·데이터는 **처음부터 새로 만든 것**이다.
2. 회사 업무 프로젝트는 **설계 사고를 참고**할 수만 있다(로컬 읽기 전용).
3. 포폴 공개 전에 **회사 확인**을 받는다(참조 범위가 규정에 걸리는지).

## 허용 / 금지
| 허용 | 금지 |
|---|---|
| 계층형 UI, 서비스 분리, 알람 흐름 같은 **일반 개념** | 소스 코드, 블루프린트, 머티리얼, 위젯, 에셋 파일 복사 |
| Pixel Streaming 구축 **절차의 일반화된 재작성** | 회사 서버 주소, 포트, 계정, 문서 원문 |
| 가상 데이터센터의 자체 설계 | 실제 시설 형상/도면/좌표, 고객사 명칭·로고 |
| 공개 데이터/자체 생성 데이터 | 회사/고객 시뮬레이션 데이터 (CSV, VDB 등) |
| 클래스명/폴더명 자체 설계(`DCT` 접두) | 회사 클래스명·내부 프로젝트/패키지명 재사용 |

- [ ] 외부 에셋은 출처·라이선스를 `docs/ASSET_LICENSES.md`에 기록
