# ADR-008: 화면 흐름은 외관 → 층 → 둘러보기로 하고, 외관은 현실적인 4K 환경으로 만든다

- 상태: 채택 (2026-10-15)
- 관련: [12 Unreal 설계](../12_unreal_design.md) 12장, [09 USD 규격](../09_usd_spec.md) 12장, [11 데이터 규격](../11_data_spec.md) 9장, [ADR-007](ADR-007-unreal-specific-features.md)

## 배경
처음 설계는 홀 하나를 보여 주는 운영 화면이었다. 첫 화면을 **현실적인 데이터센터 외관(4K)** 으로 하고, 건물을 누르면 **서버 랙 공간(한 층)** 이 나타나며, 거기서 전력량과 열 이동 시뮬레이션을 확인하고, 공간을 걸어 다니는 흐름이 요청되었다.

## 결정
1. 화면을 **외관 → 층 → 둘러보기** 세 단계로 구성한다. 뒤로 가기로 거꾸로 이동한다.
2. 외관 화면은 **직접 모델링한 건물과 Unreal의 환경 기능**(하늘 대기, 구름, Lumen, 랜드스케이프, Nanite)으로 현실적으로 만든다.
3. **자세히 만드는 층은 하나**(서버 랙 공간)로 한정한다. 다른 층은 단순 모양이다.
4. 층은 **별도 레벨(서브레벨)** 로 두고 건물 클릭 시 불러온다.
5. 전력량과 효율(PUE)은 **게이트웨이가 센서 값에서 계산한 집계 값**으로 보여 주며, 합성한 추정값임을 화면에 표시한다.
6. USD 구조는 기존 `/DC/Hall01/...`을 유지하고 `/DC/Building01`을 옆에 추가한다(센서 ID와 검증 규칙 유지).
7. 4K는 exe와 녹화 영상의 목표이고, Pixel Streaming 기본은 1080p로 시작해 E3 측정 후 정한다.
8. 외부 환경 에셋은 저장소에 올리지 않고 출처와 받는 방법을 문서화한다.

## 근거
- 외관에서 안으로 들어가는 흐름은 시설 전체 맥락(건물 전력, 효율)에서 개별 장비(랙 센서)로 내려가는 **디지털 트윈의 전형적인 탐색 방식**이다.
- 현실적인 외부 환경은 Unreal이 기본 제공하는 기능이 강한 영역이라 Unreal을 쓰는 근거를 강화한다(비교는 E2에서 측정).
- 층 하나만 자세히 만들어 범위를 통제한다.

## 우선순위 (2026-10-15 추가)
이 프로젝트에서 **가장 중요한 것은 Omniverse 계열 시뮬레이션과 센서 데이터의 Unreal 연동·표현**이다([14 핵심 설계](../14_sim_to_unreal_core.md)). 외관과 환경은 **보조**이므로 다음 순서로 진행한다.
1. **최소 외관**(단순한 건물, 기본 하늘과 땅, 건물 클릭으로 층 진입)을 먼저 만든다.
2. 핵심(Phase 3~5)이 동작한 뒤, 시간이 있으면 **현실적인 4K 환경**으로 다듬는다.
일정이 부족하면 외관의 현실화를 줄이고 핵심에 시간을 쓴다.

## 대안
| 대안 | 제외한 이유 |
|---|---|
| 홀 화면만 제공 | 첫인상과 맥락이 약하다. |
| 여러 층을 모두 자세히 구현 | 모델링과 시뮬레이션 비용이 너무 커진다. |
| 외관을 외부 구매 모델로 구성 | 직접 제작 방침과 라이선스(재배포) 문제 |
| 층 전체를 한 레벨에 포함 | 외관 화면이 무거워진다. |

## 영향과 한계
- **일정이 약 2.5주 늘어난다**(Phase 5.5 추가, 총 약 17주). MVP(Phase 0~3)는 그대로다.
- 건물 외관 모델링과 환경 구성이 추가된다. 모델링 가이드는 외관 작업 전에 보완한다.
- 4K와 Pixel Streaming은 부담이 크다. 측정 전에는 기본 해상도를 확정하지 않는다.
- 외부 환경 에셋을 저장소에 올리지 않으므로, 저장소를 받은 사람이 환경 에셋을 따로 받아야 외관을 똑같이 재현할 수 있다.
- PUE와 전력 집계는 시각화용 추정이다.
