# ADR-007: 운영 화면에 Unreal 고유 기능과 내부 둘러보기를 포함한다

- 상태: 채택 (2026-10-15)
- 관련: [ADR-001](ADR-001-roles-omniverse-vs-unreal.md), [12 Unreal 설계](../12_unreal_design.md) 10장과 11장, [03 비교 실험](../03_experiments.md) E2

## 배경
시뮬레이션과 데이터를 Omniverse 기반으로 하기로 하면서([ADR-006](ADR-006-omniverse-based-simulation.md)), 운영 화면을 Unreal로 만드는 이유가 더 분명해야 한다. 또한 데이터센터 내부를 직접 걸어 다니며 보는 기능이 요청되었다.

## 결정
1. 운영 화면에 **내부 둘러보기**(1인칭 걸어 다니기, 안내 투어, 알람 현장으로 이동)를 포함한다.
2. **Unreal에서 기본 제공되어 구현 비용이 낮은 기능**(1인칭 이동과 충돌, 상호작용, 나이아가라 효과, 시퀀서 연출과 녹화, 공간 음향)을 기본 범위로 한다.
3. 훈련 모드, 음성 안내 어시스턴트, 다중 화면 관제실은 선택 항목으로 둔다.
4. "Omniverse로는 만들 수 없다"고 단정하지 않는다. **같은 기능을 양쪽에서 만드는 비용을 E2에서 측정**한다.

## 근거
- 시뮬레이션은 Omniverse, 현장감과 상호작용은 Unreal이라는 역할 분리가 기능 수준에서 드러난다.
- 걸어 다니기와 안내 투어는 운영자에게 실제로 쓸모가 있고(알람 현장 확인), 포트폴리오 영상으로도 효과가 크다.
- 주장이 아니라 비용 측정으로 근거를 남긴다.

## 대안
| 대안 | 제외한 이유 |
|---|---|
| Unreal 고유 기능 없이 3D 뷰와 패널만 | Unreal을 쓰는 이유가 약해진다. |
| 선택 기능(MetaHuman 등)까지 모두 기본 범위에 포함 | 일정이 늘고 데이터센터 주제에서 멀어진다. |

## 영향과 한계
- Phase 5가 2주에서 3주로 늘어난다([02 로드맵](../02_roadmap.md)).
- 방은 따로 모델링하지 않는다. 바닥, 벽, 천장은 장면 생성 스크립트가 상자로 만들고 충돌로도 쓴다. 통로 폭 기준만 지킨다([09](../09_usd_spec.md) 11장).
- 눈높이에서는 한 화면에 보이는 장비가 많아 성능 부담이 커진다. 측정 전에는 목표를 확정하지 않는다.
- Pixel Streaming에서 마우스 잠금 지원 여부가 불확실하다(Phase 6에서 확인).
