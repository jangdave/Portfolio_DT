# ADR-004: 서비스 호스팅 전략 (GPU 서버 없는 개인 포트폴리오)

- 상태: 채택 (B·C 세부 방식은 Phase 6에서 검증 후 갱신)
- 날짜: 2026-10-15
- 관련: [ADR-003](ADR-003-delivery-and-ui.md)

## 배경
Pixel Streaming은 접속 세션마다 GPU로 렌더링하는 서버가 필요하다. 개인 포트폴리오라서 상시 운영할 GPU 서버가 없고, 열람자가 언제 접속할지도 알 수 없다.

## 결정
상시 증거와 라이브 시연을 분리한다.

| 구분 | 방식 | 비용 | 용도 |
|---|---|---|---|
| A. 상시 산출물 | 데모 영상(YouTube 등 외부 호스팅) + Windows 패키지(GitHub Releases) | 무료 | 열람자가 언제든 확인 |
| B. 본인 PC 라이브 | 개발 PC(RTX 5090)에서 스트리밍, 터널 또는 VPN으로 외부 접속 | 무료 | 면접·시연 시 |
| C. 임시 클라우드 GPU | 필요한 기간에만 GPU 인스턴스를 켜서 공개 링크 운영 | 사용 시간만큼 과금 | 기간 한정 공개 데모, E3 원격 지연 측정 |

- **A를 기본 산출물로 한다.** 영상은 GitHub LFS 한도를 쓰지 않도록 외부에 올리고 README에는 링크만 둔다. Windows 패키지는 Releases 자산으로 배포한다(파일 크기 한도는 Phase 6에서 확인).
- **B는 면접 시연용이다.** PC를 켜 둔 시간에만 가능함을 문서에 명시한다.
- **C는 선택이다.** 공개 링크가 꼭 필요한 시점에만 쓰고, 상시 운영하지 않는다.

## 근거
- 프로젝트의 핵심 증명은 UE 클라이언트 구현과 데이터 파이프라인이며, 스트리밍은 배포 방식 중 하나다. 라이브 서버가 없어도 설계와 구현의 평가는 유지된다.
- E3(서비스 방식 비교)의 exe·LAN 스트리밍 측정은 로컬로 충분하다. "원격" 지연은 C로 한두 번 측정하면 된다.
- 비용이 발생하는 항목(C)을 선택 사항으로 두어 프로젝트의 재정적 부담을 없앤다.

## 검증할 것 (Phase 6)
- [ ] B: 터널만으로 WebRTC 영상이 전달되는지, TURN 서버가 필요한지
- [ ] B: 외부 접속 시 시그널링 서버 노출 범위와 보안(인증, 접근 제한)
- [ ] C: 클라우드 GPU의 현재 가격, 지원 OS(Windows 패키지 기준), 구성 시간. 확인 날짜와 조건을 기록
- [ ] A: GitHub Releases 자산 크기 한도와 패키지 용량

## 대안
- 상시 GPU 서버 운영: 비용과 관리 부담이 크고, 열람자 접속 빈도를 고려하면 효용이 낮아 제외.
- WebGL/브라우저 네이티브 렌더링으로 전환: 프로젝트의 UE 클라이언트 증명 목적과 맞지 않아 제외.

## 한계
- 열람자가 포폴을 보는 시점에 즉시 체험해 볼 수 있는 상시 데모는 제공하지 않는다. 영상과 다운로드 가능한 패키지로 대체한다.
- B의 외부 접속은 네트워크 환경(공유기, 방화벽)에 따라 안 될 수 있다.
