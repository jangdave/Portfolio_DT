# ADR-009: 홀은 랙 60기 규모로 만들고, 냉각은 공기 방식(뜨거운 통로 격벽 + 바닥 급기)부터 시작한다

- 상태: 채택 (2026-10-15)
- 관련: [09 USD 규격](../09_usd_spec.md) 11장, [14 핵심 설계](../14_sim_to_unreal_core.md), [실증 결과 E0](../../experiments/results/E0_omniverse_capability_probe.md)

## 배경
처음 시험은 랙 10기와 CRAC 2기의 작은 홀이었다. 구조를 갖추려면 실제 데이터센터에 가까운 규모와 냉각 방식이 필요하다는 요청(랙 50기 이상, 대형 사업자가 쓰는 방식)이 있었다. 내부 구조를 먼저 모델링하고, 시뮬레이션을 돌려, Unreal에서 확인하는 순서로 진행하기로 했다.

## 결정
1. 랙 **60기**(6줄 x 10기), CRAC 8기, 홀 11.0 x 13.6 x 4.0 m.
2. 줄 2개가 차가운 통로(폭 120 cm)를 사이에 두고 앞면을 마주 보고, 뒷면은 뜨거운 통로(폭 100 cm)를 만든다. 줄은 CRAC와 직각이며, CRAC는 뜨거운 통로 끝에 둔다.
3. **1단계는 공기 방식**: 뜨거운 통로 격벽(지붕과 옆면 패널) + CRAC 회수 + 차가운 통로 바닥 급기구.
4. **2단계는 혼합 방식**(칩 직접 액체 냉각 + 줄 사이 열교환 모듈 + CDU): 1단계가 끝까지 동작한 뒤 추가한다. 발열을 액체 몫과 공기 몫으로 나누는 비율은 설정값으로 둔다.
5. 배치의 원본은 `usd/scenes/hall01.config.json`이고 장면은 `scripts/usd_tools/build_scene.py`가 만든다. 나중에 Unreal에서 랙을 옮기고 시뮬레이션을 다시 돌릴 수 있도록, 시뮬레이션 입력은 장면 USD에서 읽는다.

## 근거 (2026-10-15 웹 조사, 모두 제조사·언론 자료이며 표준 원문은 확인하지 못함)
- 앞면끼리 마주 보는 차가운 통로와 뒷면끼리 마주 보는 뜨거운 통로, 줄과 공조기를 직각으로 두는 방식은 서버 설치 지침(Oracle, IBM)에 공통으로 나온다.
- 차가운 통로 1.2 m, 7타일(약 4.3 m) 간격은 TechTarget, Rack Solutions 자료를 따랐다. 우리 랙 깊이가 100 cm라서 줄 쌍의 간격은 4.2 m가 된다.
- 새 대형 시설은 뜨거운 통로 격벽을 많이 쓰고(SVL), AWS와 NVIDIA 참조 설계는 칩 직접 냉각에 공기 냉각을 섞은 혼합 방식이다(AWS IRHX, HPE·Vertiv의 GB200 NVL72 자료). 그래서 혼합 방식을 2단계로 둔다.
- 천장 높이, 바닥 아래 공간(플레넘) 깊이, 랙당 CRAC 수는 조사에서 표준값을 찾지 못했다. **천장 4.0 m와 CRAC 8기(랙 7.5기당 1기)는 근거 없이 정한 가상 값이다.**
- 통신사 데이터센터의 냉각 방식과 팬 월, 증발식 냉각은 확인하지 못했다.

## 대안
- 처음부터 혼합 방식: 구조는 현실에 가깝지만 모델링할 장비가 4종 늘고 발열 분할 근거도 없어서, 범위가 커진다.
- 줄 2개짜리 작은 홀 유지: 빠르지만 줄 끝과 가운데 랙의 차이, 통로 구조를 보여 주지 못한다.

## 한계
- 시각화 목적이다. 공학적 정확성을 주장하지 않는다.
- 이 장면은 가상 시설이며 실제 설계나 제품을 따라 하지 않았다.
- 격벽 위쪽 누설, 바닥 아래 공기 흐름은 처음에는 단순하게 다룬다.
