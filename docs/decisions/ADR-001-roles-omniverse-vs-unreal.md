# ADR-001: 시뮬레이션/저작은 Omniverse 계열, 운영자 클라이언트는 Unreal

- 상태: 채택 (검증 대기: E2, E3)
- 날짜: 2026-10-15

## 결정
저작·데이터 생성은 OpenUSD/Omniverse 계열, 운영자용 클라이언트는 UE로 구현한다. 엔진 버전은 [ADR-010](ADR-010-unreal-engine-5-8.md)에서 5.8로 정했다(처음 결정은 5.7).

## 근거
1. 시뮬레이션은 무겁고 한 곳에서, 클라이언트는 가볍고 다수에게 배포되는 성격이라 분리하는 편이 자연스럽다.
2. 디지털 트윈 클라이언트 실무에서 UE 자산·인력·파이프라인이 이미 존재하는 경우가 많아 "Omniverse 데이터를 UE 클라이언트에 연결"하는 요구가 현실적이다.
3. 목표 직군(UE 클라이언트 개발자)의 역량을 직접 보여준다.

## 대안
Omniverse 단독 구현(Kit 앱/ovrtx 뷰어). → E2에서 같은 씬으로 비교한다.

## 정정 (2026-10-15, 설계 재점검 후)
- 처음 표현은 "시뮬레이션/저작은 Omniverse 계열"이었다. 실제로는 **OpenUSD(장면 형식)와 Omniverse 라이브러리(ovrtx 렌더링)** 만 쓰고, 센서 값과 열·기류 데이터는 일반 Python 코드가 만든다. Kit 앱(Replicator, Isaac Sim 등)은 설치하지 않았다.
- 이후 **시뮬레이션과 데이터도 Omniverse 계열로 만들기로 결정**했다. [ADR-006](ADR-006-omniverse-based-simulation.md)과 [08 설계 재점검](../08_design_review.md) P4.

## 한계 / 정직한 주의
- Omniverse 단독이 충분한 용도(제작자용 뷰, 합성 데이터)가 있다.
- 성능·배포 우위는 가설이며 E2/E3 결과로 대체한다.
- 범위를 "운영자용 클라이언트 앱"으로 한정해서 주장한다.
