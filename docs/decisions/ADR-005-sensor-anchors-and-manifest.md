# ADR-005: 센서는 앵커 prim으로 정의하고 매니페스트로 전달한다

- 상태: 채택
- 날짜: 2026-10-15
- 관련: [08 설계 재점검](../08_design_review.md) P1, P2, P3 / [09 USD 규격](../09_usd_spec.md) / [11 데이터 규격](../11_data_spec.md)

## 배경
- 처음 규칙은 장비 prim 하나에 센서 ID 하나(`dct:sensorId`)를 붙이는 방식이었다. 랙에는 센서가 여럿(입구 온도, 출구 온도, 전력)이라 이 방식으로는 나타낼 수 없다.
- 센서 ID, MQTT 주소, USD 경로의 대응 규칙이 없었다.
- Unreal이 실행 중에 USD의 사용자 속성을 읽을 수 있는지 확인하지 않았다.

## 결정
1. **센서 하나를 센서 앵커 prim 하나로 정의한다.** 장비 아래 `Anchors/Sensor_<METRIC>`에 두고 `dct:sensorId`, `dct:metric`, `dct:unit`을 붙인다.
2. **센서 ID와 MQTT 주소는 USD 경로에서 계산한다.** 장비 번호는 홀 안에서 겹치지 않게 매긴다. 변환 코드는 한 곳(매니페스트 생성 스크립트)에만 둔다.
3. **센서 매니페스트(JSON)를 USD 장면에서 자동 생성**하고, 생성기, 게이트웨이, Unreal이 모두 이 파일을 기준으로 삼는다. Unreal은 USD 속성에 의존하지 않는다.
4. **알람 판정은 게이트웨이 한 곳에서** 한다. Unreal은 표시만 한다.

## 근거
- 센서를 prim으로 만들면 센서마다 3D 위치를 가질 수 있어 화면에서 센서 위치에 표시를 붙이기 쉽다.
- 경로에서 계산하면 같은 정보를 여러 곳에 손으로 적을 필요가 없고, 어긋남을 검사로 잡을 수 있다.
- 매니페스트를 두면 Unreal이 USD 속성을 읽지 못해도 진행할 수 있다(위험 제거).
- 판정 규칙이 한 곳에 있으면 서로 어긋나지 않고 Unreal 없이 시험할 수 있다.

## 대안
| 대안 | 제외한 이유 |
|---|---|
| 장비 prim에 센서 속성 여러 개(`dct:sensor:temp_in:id` 식) | 속성 이름 규칙이 복잡하고 센서 위치를 따로 가질 수 없다. |
| Unreal이 USD 속성을 직접 읽음 | 지원 여부가 확인되지 않았다. 되더라도 점검용으로만 쓴다. |
| 알람을 Unreal에서 판정 | 규칙이 두 곳에 생기고, 자동 시험이 어렵다. |

## 결과와 한계
- 검증 스크립트(v1)를 개정해야 한다([이슈 #10](https://github.com/jangdave/Portfolio_DT/issues/10)). 현재 `usd/assets/rack.usda`의 센서 앵커도 v2 형식으로 고쳐야 한다.
- 매니페스트가 USD와 어긋나지 않도록 생성 스크립트와 개수 점검 테스트가 필요하다([이슈 #12](https://github.com/jangdave/Portfolio_DT/issues/12)).
- 센서가 늘어나면 매니페스트가 커진다. 처음 규모(80개)에서는 문제가 없었고, 지금 204개에서도 문제가 없다.
