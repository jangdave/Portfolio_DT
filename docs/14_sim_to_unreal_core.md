# 14. 시뮬레이션과 센서 데이터의 Unreal 연동·표현 (핵심 설계)

- 상태: 초안 v1 (2026-10-15)
- 목적: 이 프로젝트에서 **가장 중요한 부분**인 "Omniverse 계열 시뮬레이션이 만든 센서 데이터를 Unreal이 받아서 알아보기 쉽게 표현하는 것"의 설계를 한 곳에 모은다.
- 읽는 사람: 프로젝트를 이어받는 개발자, 포트폴리오를 검토하는 사람
- 관련 문서: [11 데이터 규격](11_data_spec.md), [12 Unreal 설계](12_unreal_design.md), [13 Omniverse 연구 계획](13_omniverse_research.md), [ADR-006](decisions/ADR-006-omniverse-based-simulation.md)

## 1. 우선순위

| 구분 | 내용 | 비중 |
|---|---|---|
| **핵심** | ① Omniverse 계열 시뮬레이션(Warp 열 시뮬레이션, 가상 센서) ② 센서 데이터를 Unreal로 연동 ③ 데이터를 3D로 표현 | 가장 크다. 시간과 품질을 여기에 먼저 쓴다. |
| 보조 | 건물 외관, 현실적인 환경(4K), 내부 둘러보기, 안내 투어 | 핵심이 동작한 뒤 더한다. 외관은 **최소 버전(단순 건물과 기본 하늘)** 부터 만든다. |

일정이 부족하면 보조 항목부터 줄인다. 핵심이 흔들리면 다른 항목이 있어도 프로젝트의 가치가 떨어진다.

## 2. 연동 경로

시뮬레이션 결과가 Unreal에 닿는 길은 네 가지다.

| 경로 | 보내는 것 | 방식 | 특징 |
|---|---|---|---|
| A. 정적 장면 | 장비 구조, 센서 위치와 목록 | USD 가져오기 + 센서 매니페스트 | 한 번만. 모든 데이터를 장비와 연결하는 기준 |
| B. 실시간 센서 | 온도, 전력, 팬 속도 등 센서 값과 알람 | 시뮬레이션 → MQTT → 게이트웨이 → WebSocket | 1초 단위. 가볍다. |
| C. 미리 계산한 부피 | 온도장(열이 퍼진 모양) | Warp(NanoVDB) → 변환 → VDB 시퀀스 → Unreal 재생 | 무겁다. 시간에 맞춰 재생한다. |
| D. 직접 연동 (조사) | 장면 변경 실시간 동기 등 | Omniverse와 Unreal의 공식 연동 도구 | **현재 지원 상태를 확인하지 못했다.** 연구 R7에서 조사 |

### 2.1 B와 C를 맞추는 방법
센서 값(B)과 부피(C)는 **같은 시뮬레이션에서 나온 같은 시간축**을 쓴다.

- 시뮬레이션이 한 번 실행되면 **센서 스트림(`.jsonl`)과 부피 프레임(시뮬레이션 시간이 붙은 VDB 시퀀스)을 함께 기록**한다.
- Unreal은 현재 재생 시간에 가장 가까운 부피 프레임을 보여 주고, 센서 값은 같은 시간의 샘플을 쓴다.
- **기본 데모는 이 "시나리오 녹화본 재생"** 이다. 센서와 부피가 정확히 맞아떨어지고, 같은 결과를 반복해서 보여 줄 수 있다.
- **라이브 모드**(시뮬레이션을 실시간으로 돌리면서 보기)에서는 센서 값만 실시간이고, 부피는 지원하지 않거나 낮은 빈도로 갱신한다. 한계를 문서와 화면에 밝힌다.

### 2.2 센서와 부피의 교차 검증
부피 데이터에서 **센서 위치의 값을 읽어 센서 값과 비교**한다. 두 값이 허용 오차 안에서 같아야 한다.
- 이 검사로 "센서는 맞는데 부피가 어긋난" 문제를 잡는다.
- 허용 오차는 Phase 4에서 측정해서 정한다. (측정 전에는 수치를 정하지 않는다.)

## 3. 표현 매핑표 (무엇을 어떻게 보여 주는가)

이 표가 "표현"의 핵심이다. 데이터마다 보여 주는 방식과 쓰는 Unreal 기능을 정한다.

| 데이터 | 3D에서 보이는 모습 | Unreal 기능 | 한계 |
|---|---|---|---|
| 입구·출구 온도(`temp_in`, `temp_out`) | 서버 앞면과 뒷면이 온도에 따라 색이 변한다. 랙 위에 수치 라벨 | 인스턴스별 값(Custom Primitive Data), 머티리얼, 위젯 | 색 범례를 함께 보여 준다. |
| 온도장(부피) | 공간 전체가 열 분포로 채워진다. **단면 평면**을 움직여 특정 높이의 온도를 본다. | 부피 렌더(이종 볼륨), 희소 볼륨 텍스처, 평면 이동 | 해상도와 용량에 제한. 녹화본 재생에서 지원 |
| 공기 흐름 | 냉기는 파란 입자, 열기는 주황 입자가 흐른다. | 나이아가라 | L1에서는 정해 둔 흐름을 표현한다. 실제 계산 결과가 아니다. |
| 랙 전력(`power`) | 랙 위 막대와 발광이 전력에 따라 변한다. | 머티리얼, 위젯 | |
| PDU 부하(`load`) | 부하율 게이지, 임계에 가까우면 색 변화 | 위젯, 머티리얼 | |
| 팬 속도(`fan_speed`) | 팬 날개가 속도에 맞춰 돌고, 소리의 크기와 높낮이가 변한다. | 회전 애니메이션, MetaSounds | 팬 메시를 분리해서 모델링해야 한다. |
| CRAC 공급·회수 온도 | 공급구에서 찬 공기, 회수구에서 더운 공기 입자 | 나이아가라 | |
| 알람 | 해당 장비가 외곽선과 발광으로 강조되고, 알람 목록과 경보음이 나오며, 누르면 카메라가 이동 | 후처리 머티리얼(커스텀 스텐실), 위젯, 카메라 | |
| 품질 이상(`stale`, `bad`) | 회색으로 바뀌고 물결 무늬 또는 "끊김" 표시 | 머티리얼, 위젯 | |
| 집계(전력량, PUE) | 요약 패널, 외관 화면의 라벨 | 위젯 | 합성한 추정값이라고 표시 |
| 시간 | 재생 막대(일시정지, 배속, 되감기) | 위젯, 녹화 파일 재생 | 녹화본 재생에서만 되감기 가능 |

- 값 → 색 변환은 **한 곳**(색 곡선과 정규화 함수)에서만 정의하고, 자동화 테스트로 확인한다([12](12_unreal_design.md) 8장).
- 색만으로 상태를 구분하지 않는다. 아이콘과 글자를 함께 쓴다.
- 표현이 많아질수록 화면이 복잡해지므로, **한 번에 켜는 표현은 3개 이하**로 시작한다(예: 온도 색, 알람 강조, 수치 라벨). 나머지는 토글로 켠다.

## 4. 시간과 재생

| 기능 | 설명 |
|---|---|
| 현재 시간 표시 | 화면 위에 시뮬레이션 시간을 표시한다. |
| 일시정지, 배속 | 녹화본 재생 시 지원. 라이브는 일시정지만 가능(값은 계속 받고 화면만 멈춤) |
| 되감기, 시점 이동 | 녹화본 재생 시 재생 막대를 끌어 시점을 옮긴다. 센서 값, 알람 이력, 부피가 함께 이동한다. |
| 값 사이 보간 | 센서 값 사이를 0.5초 정도에 걸쳐 부드럽게 바꿔서 색이 툭툭 끊기지 않게 한다. |

되감기와 재생 제어는 알람이 **왜** 났는지 돌아보는 데 쓸모가 있고, 포트폴리오 영상에서도 효과적이다.

## 5. 지연 예산 (측정 전 가정)

센서 값이 만들어져서 화면에 반영될 때까지의 목표다. **가정이며 Phase 3에서 측정해서 조정한다.**

| 단계 | 목표 |
|---|---|
| 생성 → MQTT 발행 | 10 ms 이하 |
| MQTT → 게이트웨이 | 20 ms 이하 |
| 게이트웨이 처리(알람 판정 등) → WebSocket 전송 | 30 ms 이하 |
| Unreal 수신 → 다음 프레임 반영 | 50 ms 이하 |
| **전체** | **약 100~200 ms** (사람이 느끼기에 거의 실시간) |

**측정 방법:** 생성기가 샘플마다 순번(`seq`)과 발행 시각을 기록하고, Unreal이 화면에 반영한 시점을 같은 시계 기준으로 로그에 남겨 차이를 계산한다. 같은 PC에서 돌리므로 시계 차이는 없다. 원격 스트리밍 때는 별도 방법을 쓴다(E3).

## 6. 검증

| 확인할 것 | 방법 |
|---|---|
| 값 → 색 변환이 맞는가 | Unreal 자동화 테스트: 경계 값(최소, 범위 중간, 최대, 범위 밖) |
| 센서 위치가 3D에서 같은 위치인가 | E1: 앵커 위치 오차 측정 |
| 센서와 부피가 맞는가 | 2.2장의 교차 검증 |
| 지연이 목표 안인가 | 5장의 측정 |
| 알람이 같은 순서로 뜨는가 | 같은 녹화본을 재생해 알람 순서를 비교 |
| 연결이 끊겼을 때 | 게이트웨이를 껐다 켜며 화면 표시와 복구 확인 |

## 7. 데모 이야기 (`cooling_failure`)

1. 정상: 랙이 푸른 계열 색이고 공기 흐름 입자가 부드럽게 흐른다. 팬 소리가 일정하다.
2. 60초: `CRAC_02` 팬이 멈춘다. 팬 날개가 멈추고 소리가 사라지고 냉기 입자가 줄어든다.
3. 가까운 랙부터 온도가 올라 색이 노랑 → 주황으로 변하고, 온도장 부피가 열기로 채워진다. 단면 평면을 움직여 보여 준다.
4. **주의 알람**: 해당 랙이 강조되고 알람 목록에 올라오며 경보음이 난다.
5. **위험 알람**: 더 많은 랙으로 번지고, 전력 효율(PUE)이 나빠진다.
6. 알람을 눌러 해당 장비로 이동하고(필요하면 1인칭으로 걸어 들어가 확인), 재생 막대로 되감아서 **원인 시점**을 다시 본다.

## 9. 위험
| 위험 | 대응 |
|---|---|
| Warp 열 시뮬레이션이 그럴듯하게 나오지 않음 | 기준선(L0, 간단한 모델)로 센서 파이프라인과 표현을 먼저 완성 |
| 부피 데이터 변환이 막힘(R6) | 3D 텍스처 이미지 묶음 방식, 또는 부피 없이 단면 이미지로 대체 |
| 표현이 너무 많아 화면이 복잡 | 한 번에 3개 이하, 나머지는 토글 |
| 직접 연동 경로(D)가 없음 | 이 프로젝트는 B와 C로 구성되어 D 없이도 성립. D는 비교 대상으로만 조사 |
