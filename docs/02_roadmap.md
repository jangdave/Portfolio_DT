# 02. 로드맵 (약 13주, 단계별 산출물)

각 Phase는 **끊어도 결과물이 남도록** 구성한다. 기간은 주당 투입 시간에 따라 조정한다.

| Phase | 기간 | 목표 | 산출물 / 완료 기준 |
|---|---|---|---|
| 0. 작업 환경 설정 | 0.5주 | 저장소, 규칙, 환경 점검 | `check_env.ps1` 통과, `05_env_status.md`, ADR-001~003 |
| 1. USD·Omniverse 기초 | 1.5주 | USD 규격 확정, 검증, 랙 파이프라인, ovrtx 렌더 확인 | 랙 1기 USD(직접 모델링), USD 규격 [09](09_usd_spec.md), 검증 스크립트 v2, ovrtx 렌더 이미지 |
| 2. 모델링 + UE 임포트 | 2.5주 | CRAC·PDU·방 모델링, 장면 생성, 센서 매니페스트, UE 가져오기 | 홀 1개 USD 장면(랙 20기), 센서 매니페스트(80개), UE 맵, **E1 변환 손실 표**, 결정 D1·D3 |
| 3. 실시간 데이터 | 2주 | 센서 값 생성기 → MQTT → 게이트웨이 → UE | 시나리오 4종, 알람 판정, 녹화·재생, UE 센서 패널 실시간 갱신 |
| 4. 열·기류 볼륨 | 1.5주 | VDB 생성 → UE 볼륨 표시 | 도구 시험과 결정 D2, PoC 영상, 방식 ADR |
| 5. 클라이언트 완성 | 2주 | 알람, 하이라이트, 트렌드, 카메라 이동 | 데모 시나리오 1~3 재현 |
| 6. 스트리밍·배포 | 1주 | PixelStreaming2 + exe 패키징, 혼합 UI | 웹 접속 데모, 웹 패널 1~2개 |
| 7. 비교 실험 | 1.5주 | E2~E4 측정 | 결과표·그래프, 결론 문서 |
| 8. 포폴 정리 | 1주 | 영상, 문서, Notion 반영 | 데모 영상 2분, 아키텍처 다이어그램, README |
| (선택) 9. AI 확장 | 2주 | LLM 알람 요약 / 합성 데이터 | 별도 ADR 후 진행 |

## 최소 성공선 (MVP)
Phase 0~3 + 5의 일부: **USD 씬 → UE 임포트 → 라이브 센서 → 알람 하이라이트.** 여기까지가 약 6주이며 이것만으로도 포폴 한 페이지가 된다.

## 리스크
| 리스크 | 대응 |
|---|---|
| UE 5.7 USD 임포트 손실이 큼 | E1에서 손실을 정량화하고, 필요하면 FBX/Datasmith 보조 경로를 ADR로 기록 |
| VDB 시각화 품질/용량 | 해상도·프레임 수를 작게 시작, 예산표 작성 |
| Pixel Streaming 외부 접속 | 데모는 영상 기본, 라이브는 로컬/임시 클라우드 |
| 범위 팽창 | 홀 1개, 랙 20기 이내, 시나리오 4개로 고정 |
| 회사 자산 혼입 | `04_clean_room_policy.md` 체크리스트, 커밋 전 점검 |
